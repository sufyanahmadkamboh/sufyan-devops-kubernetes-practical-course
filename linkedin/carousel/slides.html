Concept · desired state

You declare. Kubernetes keeps it true.

Deploymentreplicas: 3
image: backend:2.0.0
ReplicaSet"3 wanted, 2 running"
→ create one
Pods3 running again
on any healthy node
Delete a Pod and it comes back. Update the image and old Pods are replaced one by one; a bad image stops the rollout while the old version keeps serving, and kubectl rollout undo brings it back.
Concept · Services and labels

One stable name for Pods that come and go

$ kubectl describe service backend-service Selector: app=back-end Endpoints: $ kubectl get pods --show-labels backend-…-5jt79 1/1 Running app=backend
A Service finds its Pods by their labels. One typo in the selector and it has no endpoints: every Pod is healthy, and every request fails.
Concept · NetworkPolicies and RBAC

Only the allowed paths, only the allowed people

ingress→ frontend :8080
frontend→ backend :8080
backend→ database :5432
$ kubectl auth can-i list pods --as developer yes $ kubectl auth can-i delete pods --as developer no
Default-deny policies enforced by Calico (the frontend can never reach the database), and a read-only Role for people.
